## Background

I work in sales, not software. Before this, nothing I had built had any user
besides me.

Two things existed going in. One was a chat workflow, [WorkBuddy and the
Margin Magician](/projects/workbuddy-margin-magician/), which had been
answering the team's sales questions for about ten months. The other was
several months of [building games with AI](/?p=games) — text-based games
with dashboards and rules engines — which established that a chat session
could produce working software rather than only answers.

## The outputs were already programs

The transition shows up in the project folder before it was named. In
mid-May 2026 a request for an order checklist returned an HTML file: a
working page with checkboxes rather than a list. On May 26 a single
morning's questions produced a dozen interactive revenue charts, each one a
file that could be opened and shared.

The prompt to build an application came from the ERP vendor. Their team had
seen the Margin Magician parsing protocol and suggested it be built as an
app against their API.

## The delivery question

The open question on the evening of May 28, 2026 was how an application
reaches a phone at all — what tooling, accounts and approvals stand between
a file and something installable.

For a web app the answer is: build a single file, open it on the phone, and
use the browser's "Add to Home Screen" option. There is no build step and no
app store involved.

A prototype existed that evening under the codename Project Cerise. By the
following morning it carried the company's colours and a name.

## What version one was

<Media type="image" src="/projects/first-app/v1-first-morning.png" alt="A phone app screen with a soft mauve background: a header reading The App, a status line reading No data loaded, a greeting reading Hi Greg above instructions to upload an ERP line-item CSV with Margin Magician rules and the master customer list already loaded, and a white settings sheet with an Anthropic API key field saved locally only." caption="Version one on the morning of May 29, 2026, running again today from the original file." />

A single HTML file containing four things: the chat interface, the Margin
Magician rules as the system prompt, the master customer list embedded so
the app knew every shop and its owner, and a file picker for the weekly CSV
export from the ERP. No server, no build step, and no installation beyond
the home-screen shortcut. The file could be — and was — sent to someone as
an email attachment.

It stored the AI API key in the phone's local storage. That is workable for
a single-user tool and unworkable for anything shared, and it was replaced
within the week.

## The following week

The file was rebuilt against the ERP's live API, which removed the weekly
export step and required a server to hold the credentials the phone could no
longer keep. That is covered in [its own
post](/projects/one-worker-backend/).

On June 4, shared storage shipped — accounts, tasks, and a diary of
interactions — which changed the app from a query tool into shared
infrastructure. It had been built for two users. The whole sales team was
using it the day it appeared.

Seven days elapsed between the delivery question and software the company
ran on.
