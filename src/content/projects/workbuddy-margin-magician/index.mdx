## The workflow

A sales team runs on a recurring set of questions: who is selling what,
which shops have gone quiet, what the month looks like with a week left.

From July 2025 I answered them by exporting a line-item spreadsheet from
the ERP, uploading it into a chat, and asking in plain language. The first
logged instance is July 16, 2025 — a sales report plus a one-line request
for the month's rep numbers. It worked well enough to repeat, and it ran
for roughly ten months across several hundred conversations, on ChatGPT
first and Claude later. Two named projects came out of it.

## WorkBuddy

Eight days after that first upload, a voice conversation recorded the
intended scope: an assistant you talk through the working day with, that
asks questions back, raises the customers worth attention, and produces a
call list. That was WorkBuddy — a work companion rather than a report
generator.

The same conversation identified the constraint that capped it. Chat
memory was too small to hold a working week, and a custom GPT retains
nothing between sessions. Both limits were known going in; the chat window
was the only build surface available at the time.

## Margin Magician

The second project covered the numbers. The ERP's line-item export cannot
be handed to an AI as-is: it contains cancelled orders, sample product
that reads as revenue, internal transfers that are not sales, and three
separate date columns of which only one is meaningful.

Margin Magician was a custom GPT built to read that export correctly. It
held a set of rules — ship date is the only date that matters, dead
statuses are excluded, samples never count, internal zones are not sales —
plus a column-by-column reference for the file. It served as the team's
reporting tool for several months.

## The October failure

On October 31, 2025 it stopped producing correct output. The instructions
and the input format were unchanged; the model underneath the custom GPT
had been updated, and rules that had run reliably for three months began
failing.

There was no remedy available. The rules lived in a prompt, on a platform,
running on a model — none of which were under my control. That constraint
is the reason the app built later performs its arithmetic in ordinary
code, where a model update cannot alter the result.

## The move to a written protocol

On April 2, 2026 the work moved to Claude: a project named WorkBuddy, with
the Margin Magician rules uploaded the same day as a parsing-protocol
document. The change was that the rules stopped being a prompt inside one
vendor's product and became a document that could be read, audited, and
moved elsewhere.

That period was short. The first day produced customer-list extractions
and rep-performance breakdowns. By late May a single request returned a
set of revenue charts and reconciliations; the project folder holds a
dozen of them dated May 26, 2026.

Two days later, on May 28, the same folder gained `cloudflare-worker.js`
and an HTML file carrying the app's name.

## What carried forward

The rules written for Margin Magician in April are, nearly verbatim, the
sales rules running in [the production app](/projects/one-worker-backend/)
today: ship date only, dead statuses excluded, samples never counted. The
WorkBuddy scope — surface the accounts, build the day's call list, ask
questions back — describes what the app's home screen does now.
