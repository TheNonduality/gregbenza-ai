## What I wanted

The footage back.

I pulled a 1.5GB clip off the Pico and it wouldn't open. No thumbnail, no
preview, no playback. But the file size was right — too big to be nothing. There
was clearly something in there.

## What was actually wrong

An MP4 has two parts that matter here. The `mdat` is the video itself. The `moov`
is the index — the table that tells a player where every single frame begins.

The camera writes the index *last*, when you stop recording. I'd pulled the
battery while it was still rolling, so it never got written. The footage was
sitting in the file completely intact, and every player on earth was refusing it
because the map was missing.

Nothing was lost. It was unreadable, which is a different problem.

## The easy fix wasn't available

There's a known tool for exactly this — `untrunc`. The environment doing the work
had no internet and no root, so it couldn't be installed. That left one option:
understand the file format well enough to rebuild the index by hand.

## How it got rebuilt

Rebuilding an index means knowing precisely where each frame starts and stops
inside a raw stream that has no markers you're allowed to assume.

So a healthy clip from the same camera got read byte by byte first, to learn the
exact layout — including how to tell real video frames apart from the camera's
own metadata packets sitting between them. Then a frame-boundary detector was
written from that.

And here's the part I'd do again: **the detector was tested on the healthy file
before it ever touched the broken one.** On a file where the right answer was
already known, it reconstructed all 4,477 frames exactly. Only then was it
trusted on the file where nobody knew the answer.

## What came out

**16,351 frames. Four minutes thirty-three seconds.** Then a decode check across
the entire clip: zero errors.

One thing didn't survive — the last 67 kilobytes. A single partial frame, written
at the exact instant the recording stopped. That's the frame where the battery
came out, and it's the only thing in the file that was genuinely gone.

## Then it stopped being a one-off

Two weeks later I broke another clip the same way. By then the method had been
written up as a skill with the camera's codec profile already baked in, so the
second repair needed no healthy reference file at all — just the script.
